# License Compliance

本文件是工程合规记录，不是法律意见。基线为当前仓库根目录的 `LICENSE` 与 `NOTICE`。

## 1. 当前 License

OpenAI Codex 使用 **Apache License 2.0**。`NOTICE` 当前包含：

- OpenAI Codex，Copyright 2025 OpenAI；
- Ratatui 衍生代码的 MIT 许可和相应版权声明。

Apache-2.0 同时包括贡献许可、专利许可、专利诉讼触发的终止条款、免责声明和责任限制；不授予商标权。

## 2. ForgeOS 可以做什么

在满足许可证条件时，可以：

- 使用、复制和内部部署 Codex；
- 修改源文件并开发衍生作品；
- 以源码或二进制形式再分发；
- 在商业产品/服务中使用；
- 对 ForgeOS 自有新增代码选择兼容的许可安排，但不能移除对 Codex 衍生部分的 Apache-2.0 义务。

## 3. 二次发布必须保留什么

分发源码或二进制衍生作品时至少：

1. 向接收者提供 Apache-2.0 许可证副本。
2. 在修改过的原文件中放置显著的修改声明。
3. 保留源代码中的版权、专利、商标和归属声明，排除与衍生作品无关的声明除外。
4. 若分发作品包含 `NOTICE`，在分发的 NOTICE、源码/文档或产品显示中以可读方式包含相关 NOTICE 归属。
5. 保留 Ratatui 等第三方许可/版权信息，不将 Apache NOTICE 误当成对产品的背书。

二进制分发应在安装包或随附文档中提供 `LICENSE` 和 `NOTICE`；容器/安装脚本也应把它们放在用户可访问位置。

## 4. 修改原文件的注意事项

- 不删除现有文件头、版权或第三方归属。
- 在实质修改的上游文件中加入清晰的 ForgeOS 修改说明，并可引用 Patch ID/提交历史。
- 不把纯格式化或自动生成差异伪装成 Forge 功能修改。
- 保留上游文件历史，使用 `UPSTREAM_PATCHES.md` 追踪改动理由和冲突风险。
- 生成物如果包含许可文本或第三方内容，确保构建/打包不会漏掉对应文件。
- 新增依赖前审查其 license、NOTICE、源代码提供义务和商业兼容性。

## 5. 商业化必须保留什么

- Apache-2.0 `LICENSE` 与适用的 `NOTICE`。
- OpenAI、Ratatui 和其他第三方的必要版权/归属。
- 对修改文件的显著说明。
- Apache-2.0 的免责声明和责任限制。
- 对新依赖各自许可要求的履行。

不得暗示 OpenAI 认可 ForgeOS，也不得仅凭 Apache-2.0 使用 OpenAI/Codex 商标作为自有产品标识。商业发布前应由专业法律人员复核品牌、专利、出口、隐私、遥测和第三方依赖清单。

## 6. 发布检查表

- 根发行包包含原始 `LICENSE` 和更新后的、仅追加必要归属的 `NOTICE`。
- 所有上游修改文件都有显著修改标识。
- SBOM/依赖 license 扫描完成，无未知或不兼容依赖。
- 源码包和二进制包都能找到许可文本。
- UI/CLI About 或发行文档提供第三方 notices 的入口。
- 品牌文案不暗示 OpenAI 官方关系或授权。
- Patch Registry 与发布 commit 对齐。
