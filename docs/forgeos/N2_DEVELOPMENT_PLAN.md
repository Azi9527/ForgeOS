# ForgeOS N2 Development Plan — Validation & Report Completion

> 状态：**COMPLETE（2026-08-24）**。实现与验收证据见 [N2_VALIDATION_REPORT.md](N2_VALIDATION_REPORT.md)。

## 1. 阶段目标

N2 关闭 ForgeOS V1 首个纵向切片中“Agent 已运行但工程完成证据仍不完整”的缺口。它不修改 Codex Runtime，而是在 ForgeOS 控制层建立：

```text
Pre-execution Validation Baseline
  ↓
Codex Execution / Repair
  ↓
Typed L1 Build / L2 Unit / L3 Integration
  ↓
L4 Baseline Regression Classification
  ↓
Six-dimension Human Review
  ↓
L5 Criterion-by-criterion Acceptance
  ↓
Persisted Forge Task Report
  ↓
DONE
```

核心不变量：Agent completion 不是 Task completion；只有 ForgeOS 持久证据满足状态机门禁后才能进入 DONE。

## 4. Protocol

N2 is additive. Existing schema-v1 Task and Validation files remain readable; new validation reports use schema version 2.

```text
.forge/
├─ validation/
│  ├─ baselines/<task>.json
│  ├─ results/<validation-id>.json
│  └─ regression/<regression-id>.json
└─ reports/<task>/<task-report-id>.json
```

- A baseline is captured once before the first Codex turn and is immutable.
- Current reports retain argv, timeout, bounded output and `shell=False` semantics.
- L4 compares stable check IDs derived from level, name and argv.
- A required baseline PASS becoming current FAIL/ERROR is `NEW_REGRESSION` and fails L4.
- A baseline failure that remains failing is explicitly `PRE_EXISTING_FAILURE`; L4 distinguishes it, while the required current check still prevents Validation PASS.
- Task Report is written before the Task transition to DONE; its ID is part of the DONE evidence gate.

## 5. Definition of Done enforcement

For N2-governed tasks:

- linked current Validation must pass;
- Task Report generation requires passing required L1 Build and either L2 Unit or L3 Integration command evidence;
- linked L4 Regression must pass;
- all six Review dimensions must be present exactly once and have no unresolved concern when approved;
- every declared criterion must have ordered L5 PASS evidence;
- a persisted Task Report ID must exist before DONE.

The Doctor warns when project configuration lacks required Build or Test command coverage. L4 and L5 are generated by ForgeOS rather than arbitrary shell commands.

## 6. Migration and recovery

- Old Validation schema-v1 records are loaded as current L2 evidence for inspection only.
- A legacy REVIEWING task without linked L4 evidence cannot be approved under N2. The UI exposes “退回并迁移到 N2”; the next repair/run captures a real baseline and produces N2 evidence.
- Existing DONE tasks remain readable and are not rewritten or retroactively claimed as N2-complete.
- Missing/corrupt/future evidence fails closed; no automatic model rerun is triggered during migration or startup.

## 7. Security boundaries

- Validation remains independent subprocess argv execution with `shell=False`, timeout and bounded output.
- Review and Acceptance actors reject `agent`, `codex` and `model` identities.
- UI cannot directly set Task status or forge report IDs.
- Reports reference bounded evidence; they do not embed raw SDK streams, full environment data or unbounded diffs.
- No Git mutation, upstream Codex patch, database, queue, remote server or additional Agent runtime was introduced.

## 8. Next stage

The recommended next stage is **N3 — Engineering Memory & Policy Foundations**: accepted file-backed Decision/Failure/Pattern/Task memory, bounded retrieval, minimal policy gates and audit-backed lifecycle. Vector databases, RAG platforms, Multi-Agent, Model Router and remote Web Console remain out of scope.
