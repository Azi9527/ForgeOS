# ForgeOS 企业 AI 原生平台：第一阶段开发计划

## 目标

把 ForgeOS 的一级对象从“对话”提升为“企业项目”。用户进入系统后先看到项目门户，进入项目后在同一上下文中持续完成 AI 开发、代码检查、工程验证、版本发布和运行维护。

## 信息架构

```text
企业项目中心
└── 项目
    ├── AI 开发
    ├── 代码
    ├── 验证
    ├── 发布
    ├── 运维
    └── 设置
```

对话继续使用现有 Codex 长期会话，不引入一次性任务报告流程。项目负责绑定根目录、Git 仓库、默认模型和对话集合，并逐步承载制品、环境和部署记录。

## 第一阶段范围

1. 企业项目门户：以文件夹卡片展示项目、根目录、仓库、对话和运行状态。
2. 项目入口：点击项目后恢复上一次长期开发对话；没有历史对话时创建项目上下文草稿。
3. 项目工作台：固定提供 AI 开发、代码、验证、发布、运维和设置六个入口。
4. 能力复用：代码入口复用 Git/Diff，设置入口复用项目设置与全文搜索。
5. 生命周期骨架：为验证、发布和运维建立独立工作面及项目状态占位，后续接入 Runner、Artifact、Environment 和 Deployment。

## 非目标

- 本阶段不实现 Kubernetes、多云或复杂微服务编排。
- 不重新实现 Codex Runtime、终端、Git 或文件编辑器。
- 不把对话重新包装成一次性工程任务。
- 不在尚无执行适配器时伪造发布成功或环境健康状态。

## 验收标准

- 无会话直达 URL 时默认进入项目门户。
- 项目卡片可进入开发、发布、运维和设置工作面。
- 项目工作台六个入口可导航，AI 开发仍为默认主界面。
- 项目切换后对话列表限定在当前项目，并恢复最近对话。
- 浏览器刷新和会话直达 URL 不破坏现有持续会话。
- TypeScript/Svelte 检查、前端构建与浏览器回归通过。

## 后续阶段

1. Build/Validation Runner 与证据记录。
2. Release、Artifact、Approval 和 Rollback 数据模型。
3. Environment/Deployment Adapter 与日志、健康检查。
4. 组织、成员、RBAC、凭据引用和企业审计。
