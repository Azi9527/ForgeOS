# ForgeOS 企业 AI 原生平台：第二阶段开发计划

## 目标

在项目持续开发工作区内加入按需 Build/Validation Runner 与工程证据记录。验证能力服务于开发、评审和发布复核，但不改变 Codex 长期对话的主路径，也不强制每次开发都创建任务或通过 Gate。

## 本阶段范围

1. 项目级验证配置：在项目根目录下配置构建、测试和静态检查命令。
2. 受控串行执行：复用 ForgeOS 已有终端边界，命令只能在允许的项目根目录内运行。
3. 实时运行反馈：展示当前步骤、实时输出、停止操作和失败原因。
4. 工程证据：记录命令、状态、退出码、耗时和有界输出，最多保存最近 20 次运行。
5. 跨平台命令判定：Windows 使用 PowerShell，Linux/macOS 使用 POSIX shell 退出码语义。
6. 按需使用：验证结果不自动中断持续 AI 对话，不默认成为发布硬门禁。

## 当前持久化边界

验证配置和最近证据首先保存在当前浏览器的项目级本地存储中，使用项目根目录作为隔离键。该实现可以完成单机 ForgeOS 的真实验证闭环，但还不能视为组织级、跨设备审计记录。

后续应将同一数据结构迁移到 ForgeOS 网关的项目状态存储，并增加操作者、Git commit、证据摘要、签名和不可变审计字段。迁移时应保持前端数据结构兼容，不重新实现命令执行链。

## 非目标

- 不实现远程 CI/CD 平台。
- 不自动修改项目文件或安全策略。
- 不把验证失败自动转成新的 ForgeTask。
- 不默认阻止持续对话或发布操作。
- 不在本阶段实现制品签名、审批和回滚。

## 验收标准

- 用户可以在项目验证中心配置至少一条命令并保存。
- 运行命令时可看到实时输出并可以停止。
- 命令退出码 0 显示通过，非 0 显示失败；必需检查失败后停止后续步骤。
- 刷新页面后仍可看到项目最近验证配置和证据。
- 每条证据包含命令、状态、退出码、耗时和有界输出。
- 验证工作面不影响项目持续对话、文件、Git、终端和其他二级工作面。
- Svelte 类型检查、静态构建校验和浏览器回归通过。
