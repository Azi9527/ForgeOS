# ForgeOS 企业 AI 原生平台：第三阶段交付说明

## 阶段目标

把第二阶段的单机验证工作面升级为项目生命周期底座：持续 Codex 对话仍然是开发主路径，验证、发布和运维作为项目内按需二级工作区，共享同一项目身份、Git 基线、操作者和审计边界。

## 已完成

1. 新增网关 `projectLifecycleByName` 项目状态域，按项目持久化验证、制品、发布、环境和部署记录。
2. 验证证据绑定真实 Git 分支和提交；网关覆盖客户端身份，写入当前 profile/role，并计算 SHA-256 证据摘要。
3. 验证配置最多 12 项、历史最多 20 次、单项输出最多 12,000 字符；制品、发布、环境和部署同样有界。
4. 新增制品登记、发布申请、人工审批、确认发布和回滚状态链。
5. 新增开发/测试/预发/生产环境配置，支持受控部署命令、健康检查、实时输出和有界日志。
6. 生命周期写操作复用现有角色授权和 WebSocket 审计；Viewer 只能读取。
7. 项目重命名会迁移生命周期状态，项目移除会同步移除对应状态。
8. 兼容旧网关：前端在 RPC 不可用时退回项目隔离的浏览器暂存，并明确显示“旧网关兼容模式”。

## 安全与一致性边界

- 所有命令仍通过现有受控终端执行，不新增任意远程执行后门。
- 部署和健康检查只在操作者明确点击后执行，不自动触发。
- 网关使用 revision 乐观锁防止两个页面静默覆盖项目生命周期状态。
- 操作者身份与证据摘要由网关生成，客户端提交的验证身份不被信任。
- 当前“回滚”完成发布状态和审计记录，不会静默运行项目自定义回滚脚本。

## 验证结果

- `npm run check`：通过，0 errors / 0 warnings。
- `git diff --check`：通过。
- Rust `cargo check`：已启动并完成依赖解析，但本机缺少 GNU `gcc.exe`，在 `ring` 构建脚本处停止；不是源代码诊断失败。
- Rust `cargo fmt`：当前 rustup toolchain 未安装 rustfmt component，无法执行；未为此安装大型工具链。

## 下一阶段建议

1. 用带 MSVC Build Tools 的 CI 编译并运行新增网关测试，产出可直接升级的 Windows 网关包。
2. 增加制品文件上传/对象存储适配器、服务端 SHA-256 复算和签名验证，而不只登记元数据。
3. 将发布审批升级为策略：生产环境最少审批人数、职责分离、过期审批和紧急变更流程。
4. 为部署适配 GitHub Actions、容器平台或 SSH Runner；凭据只保存引用，不进入生命周期 JSON。
5. 增加项目级审计时间线、通知路由和运行指标，形成企业运维视角。
